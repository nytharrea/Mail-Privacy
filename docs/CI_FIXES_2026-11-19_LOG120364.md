# CI fixes — logs 120364466875 / 120364467292

## Confirmed root cause

Both Android workflows failed before Android Gradle ran. `sdkmanager` printed:

`Warning: Failed to find package '\\'`

The workflow YAML had doubled backslashes (`\\`) at the end of shell command
lines. Bash therefore passed a literal backslash as an extra package argument
instead of treating it as a line continuation. The SDK package itself was not
the cause of this run.

## Fix

- Rewrote the `sdkmanager --install` invocations as single-line commands in
  both CI and Release workflows. There are no shell line continuations or
  package-name normalization/symlink guesses.
- Kept API 37 and explicitly install `platforms;android-37`.
- Kept Build Tools 36.0.0 and NDK 30.0.16248370.
- Kept `set -euo pipefail` for the SDK setup. For license acceptance only,
  temporarily disable `pipefail` around `yes | sdkmanager --licenses`, so the
  expected SIGPIPE from `yes` cannot fail the step while sdkmanager's status
  remains the pipeline status.
- Verify the exact expected file `platforms/android-37/android.jar` before
  allowing the workflow to continue.

## Preserved settings

- JDK 27
- Gradle Wrapper 9.9.1
- `compileSdk = 37`
- `targetSdk = 36`

## Verification

- Parsed both workflow YAML files.
