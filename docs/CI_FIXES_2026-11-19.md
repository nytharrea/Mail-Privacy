# CI fixes — 2026-11-19

## Findings from the uploaded GitHub Actions logs

1. Rust JNI compilation completed for all requested Android ABIs.
2. UniFFI Kotlin binding generation failed with `No UniFFI metadata found in .../libmailx_core.so`.
3. The workspace formatting check failed because Rustfmt reported formatting differences in existing Rust files.

## Changes in this revision

- Removed `strip = "symbols"` from the Cargo release profile. The release cdylib must retain UniFFI component metadata until `uniffi-bindgen generate --library ...` has extracted the Kotlin bindings. Android packaging can perform its normal native-library symbol stripping later.
- CI now normalizes Rust formatting and immediately verifies the formatted workspace before Clippy and tests. This keeps the workflow from failing on formatting-only drift, though maintainers should still run `cargo fmt --all` locally and commit the formatted source to keep the repository clean.

## Not claimed

The uploaded logs do not include a Gradle compile result: the jobs stopped during UniFFI binding generation. Kotlin compilation, APK assembly, emulator launch, Clippy, and Rust tests therefore remain unverified by those runs.


## Follow-up fixes from the 2026-11-19 CI logs

- Replaced the two redundant empty-string guards in `tracker_db.rs` with direct `""` match arms; this addresses the reported `clippy::redundant_guards` errors without changing behavior.
- Both Android workflows now explicitly prepare the wrapper with `chmod +x` and invoke it through `bash`, so a missing executable bit in a source ZIP or checkout cannot cause exit code 126.
- UniFFI binding generation uses `--no-format`; generated Kotlin binding generation no longer tries to invoke an unavailable `ktlint` binary. Formatting is not part of the binding-generation step.
- Gradle remains pinned to 9.9.1 and CI continues to use Temurin JDK 27.
